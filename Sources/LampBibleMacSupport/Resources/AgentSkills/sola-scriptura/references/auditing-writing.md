# Auditing a writing

Read this for a whole-writing audit, not for a single reader question.

1. Read the whole piece, `DEVOTIONAL_CONTEXT.md` and relevant files under `context/`
   when present. State the thesis and the chain of claims carrying it. Context can
   supply a source, but check whether that source actually carries the claim.
2. Inventory assertions doing doctrinal or factual work, not every sentence. Read
   [false-positives.md](false-positives.md) before classifying borderline claims.
3. Verify every citation from the installed modules, batching compatible passages
   and reusing text already verified. For an uncited load-bearing claim, seek the
   texts it needs using context, cross-references and targeted searches. Record what
   was checked so the search's limits remain visible.
4. Apply verdict and load using [verdicts.md](verdicts.md). Check
   [failure-patterns.md](failure-patterns.md), then try to defeat every proposed
   finding using the strongest relevant counterexample. Be equally demanding of
   claims you agree and disagree with. A language claim needing detailed analysis
   can be worked with `original-languages`; otherwise list it as unverified, not as
   an audit already completed elsewhere.
5. Consolidate repeated instances of one problem. Order by load-bearing,
   supporting, then decorative; within a load put Contrary first. Supporting
   findings deserve an entry only when consequential. Decorative findings belong
   in one closing list. Do not bury two important gaps under forty minor ones.

## The report

Open with the thesis, claims inventoried, claims actually verified and modules
consulted. A compact Claim / Verdict / Load table can show the inventory; keep
unverified claims distinct from the verdicts.

Each substantive finding has:

1. The writing's sentence, quoted.
2. The consulted text, quoted verbatim and attributed to its module.
3. The gap: what further premise the claim needs. If cumulative support comes from
   one writer, name that scope without demoting a plainly stated claim. If a term
   carries an unstated premise, unpack it rather than banning the term.
4. The smallest remedy: correct or add a citation, mark an inference or external
   dependence, or stop resting the argument on the sentence. Do not apply edits.

Include established claims in the inventory rather than manufacturing findings
about them. Findings discarded after checking can be noted briefly when useful.
Close with **What this pass did not do**: unavailable sources, unverified claims,
truncated or sampled evidence, and the useful next check. No scripture available
means only reasoning, structure and attribution were checked; say so explicitly.

In a writing workspace, an authorised Markdown report beside `draft.md` becomes a
live editor tab; say where it was saved. In read-only chat, return the report in
chat. Never promise a file you cannot write. [worked-example.md](worked-example.md)
illustrates a finding and non-findings, not a prescribed verdict for similar cases.
